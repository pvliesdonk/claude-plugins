# Hosting Workshops

Distilled craft for designing and running workshops — group sessions that produce a decision, a skill, an artifact, or shared understanding. Each session type has its own reference file with a recipe — the structure, the moves facilitators skip, the failure modes. **Identify the session type, load its file, follow it.** Don't run a session from the router alone.

## Core moves (every workshop)

Apply these before any type-specific step. Capable facilitators — humans and models — reliably do **1–2** and skip **3–6**. Check each one explicitly:

1. **Earn the workshop, then name one outcome.** A workshop is expensive. If a decision has an owner, or it's information transfer, or it's solo-depth work — don't convene; a memo, a recording, or one decider is better. If you do convene, name a *single* outcome and the tangible artifact that will prove it by the end ("what exists at 5pm?"). Not "alignment."
2. **Design backward, as a diamond — not a line.** Outcome → evidence → activities, in that order; cut any activity that doesn't feed the evidence. Schedule explicit *divergence before convergence*, and budget for the "groan zone" — the confused, frictional middle is structural, not failure; don't rescue it with a premature answer.
3. **Own the process, stay neutral on content — and fix the decision rule first.** You steer *how* the group works, never *what* it concludes. State how the decision will be made (consensus / consent / leader-decides-with-input) *before* deciding, or you get false consensus that unravels later.
4. **Generate write-first, never open-floor.** Silent individual generation before any group sharing (1-2-4-All, brainwriting). Open verbal "let's brainstorm" reliably produces *fewer* and less-original ideas than the same people alone, and lets the loudest dominate.
5. **Build safety; engineer participation structurally.** How you receive the *first* tentative contribution sets the room. Manage dominators and silence with structure (write-first, round-robins, breakouts), not by calling people out — and never read quiet as agreement.
6. **Close on owned actions; design for transfer.** End with named owners + dates and a follow-up cadence. The event is ~10% of what makes change happen — design for the experience and relationships it sets up. Don't mistake a satisfaction "smile sheet" for evidence it worked.

Then open the session-type file and follow its recipe.

## Underlying techniques (tools)

The core moves and type recipes draw on cross-cutting facilitation tools — the session arc (diverge/groan/converge/close), write-first ideation, convergence and decision methods, in-room facilitation moves (ORID, questioning, listening, neutrality), group dynamics and safety, the methods library (microstructures + large-group formats), remote/hybrid facilitation, logistics, the learning science of practice (for training), and evaluation/follow-through. When designing or running a session and you want the technique itself, see `tools.md` for the index and the matching `tool-*.md` file.
