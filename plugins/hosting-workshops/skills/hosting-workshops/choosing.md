# Choosing — Is It a Workshop, and Which One?

The most consequential facilitation decision is made before any design: *should this be a workshop at all, and if so, which kind?* Most "failed workshops" were the wrong tool, chosen before anyone asked what the job was.

## First: should this even be a workshop?

A workshop is expensive — many people's time, in one block, with prep. Rule it out first:

- **A decision with one informed owner** → they decide (gather input async); don't convene a room to ratify it. Decision theatre teaches people their input is fake.
- **Information transfer** (a briefing, an update) → a document or recording. "This could have been an email" is usually right.
- **Work needing solitary depth** (analysis, writing, deep design) → individuals alone, maybe async review.
- **Standing coordination** → a lightweight recurring ritual, not a workshop.

Convene only when the goal genuinely needs **real-time interaction among several people**: shared sense-making, cross-stakeholder negotiation, co-creation, building commitment to a decision, or hands-on practice.

## Then: classify the session

Name the **dominant purpose** (even a hybrid has one that leads):

| Dominant purpose | Type / file |
|---|---|
| Reach a decision / produce an artifact | working session → `stakeholder-workshop.md` (requirements), `strategy-offsite.md` (strategy), `threat-modeling.md` (security) |
| Generate and develop options | ideation → `tool-ideation.md` + `tool-methods.md` |
| Build a skill | `technical-training.md` |
| Improve how the team works | `retrospective.md` |
| Solve a wicked problem (with days) | `design-sprint.md` |
| Explore a question at scale | `large-group.md` (World Café) |
| Open theme, expertise in the room | `large-group.md` (Open Space) |
| Users as co-designers | `co-creation.md` |
| Incubate a field / convene research | `research-workshop.md` |

## Match the container to the goal

- **Bounded decision, fixed group** → a tightly-arced working session (`tool-the-arc.md`).
- **Explore a question, big room** → World Café (cross-pollination, not one decision).
- **Open theme, expertise present** → Open Space / unconference (let the group set the agenda).
- **Wicked problem, days available** → design sprint.
- **Deep expert synthesis** → a residential (Dagstuhl-style).
- **Just inform / one owner decides** → *not a workshop.*

The recurring error is fitting the goal to a *favourite* format (everything becomes a brainstorm, or a SWOT, or a sprint). Fit the format to the goal — which means owning a *range* of methods (`tool-methods.md`).

## Apply the core moves regardless

Earn the workshop and name one outcome; design backward as a diamond; own process / fix the decision rule; generate write-first; build safety; close on owned actions. (SKILL.md.)

## Failure modes

- **The defaulted workshop** — convening out of habit for what a memo or one decider would handle.
- **The favourite-format trap** — forcing every goal through one format.
- **Decision theatre** — putting an already-owned decision to a group.
- **Unnamed purpose** — a hybrid with no centre of gravity, so nothing lands.
