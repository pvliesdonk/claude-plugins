# Hands-On Technical Training

Teaching a technical skill is the teaching facet at full difficulty: people must leave *able to do* something, not having watched it done. Ignoring the learning-science evidence is most punishing here. The moves people skip are the practice sequence and designing for transfer — they present, and assume learning followed.

## The recipe

1. **Design from the skill backward** (`tool-the-arc.md` / backward design). Name an **observable capability** ("can deploy a container from a Dockerfile" — an apply/create verb, not "understand"), and the artifact each person builds that proves it. Then design only activities that produce it.
2. **Sequence practice on the evidence** (`tool-training-science.md`) — the heart:
   - **Worked example → completion problem → independent problem.** Start novices on a *fully worked* example (don't make them search); fade as they gain ground. Skipping to the cold open problem is the classic failure.
   - **Tier for mixed levels** — what helps novices bores experts (expertise reversal); offer a core task + stretch extensions.
   - **Make them retrieve** — low-stakes recall ("without looking, what's the command?") *is* learning, not a test (testing effect).
   - **Space and revisit** — recap-and-recall at each segment; don't cram.
   - **Fade the scaffolds** — plan removal of cheat-sheets/templates, or dependence persists.
3. **Run it** — pre-test the environment (or a tested install guide done *before*, with a sandbox fallback); a floating helper to unblock; pace hard concepts to the morning, hands-on work to the post-lunch dip.
4. **Close for transfer** — a concrete **if-then application plan** ("next time I deploy X, I'll…") and a reference to return to. The event is the 10%.

## Required moves

A strong session demos well and skips the practice design. Check each:

- [ ] **Observable capability objective + an artifact** that proves it.
- [ ] **Worked → completion → independent**, tiered for levels — no cold open problems.
- [ ] **Retrieval and spacing built in** as learning events.
- [ ] **Environment pre-tested; a helper; a fallback.**
- [ ] **Scaffolds planned to fade.**
- [ ] **An if-then application plan at the close** — designed for Monday, not just the room.

## Failure modes

- **"Understand"-level training** — watched, not reproducible; no practice with feedback.
- **Cold open problems** — novices drown while experts coast.
- **Present-once, no retrieval** — fluency illusion, poor retention.
- **The unmanaged install** — first hour lost to setup nobody pre-tested.
- **One exercise for all levels** — expertise reversal ignored.
- **No transfer close** — nothing used after the day.
