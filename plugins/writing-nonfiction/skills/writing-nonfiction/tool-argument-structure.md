# Argument Structure

Two tools for building a sound, navigable case.

## Minto Pyramid + SCQA — the structure
- **Answer first, then group the support.** The governing point sits at the apex; supporting arguments hang beneath it; evidence beneath them.
- **Each group is MECE** — Mutually Exclusive (no overlap), Collectively Exhaustive (no gaps).
- **Vertically, each point answers the question the one above provokes** ("why?" / "how do you know?"); **horizontally, the points form a logical set** (a deduction, or a parallel grouping).
- **SCQA** introduces it: Situation → Complication → Question → Answer (the apex).

## Toulmin — the anatomy of one claim
Make an argument's parts explicit so you can test and defend it:
- **Claim** — what you assert.
- **Grounds** — the data/evidence for it.
- **Warrant** — the (often unstated) principle linking grounds to claim. *Surface it* — that's where arguments break.
- **Backing** — support for the warrant itself.
- **Qualifier** — the strength ("usually", "in most cases"); match it to the evidence.
- **Rebuttal** — the conditions under which it wouldn't hold; pre-empt the reader's objection.

## Apply it
- Draft the one-sentence governing claim; check every section supports *it*, and the support is MECE.
- For a contested claim, write grounds → warrant → backing; if the warrant is shaky or unstated, so is the argument.
- Name the strongest objection and answer it (rebuttal) before the reader raises it.

## Failure modes
- **No apex** — a pile of facts with no governing point.
- **Overlapping or incomplete groups** — not MECE.
- **Hidden warrant** — a leap from evidence to claim the reader won't grant.
- **Overclaiming** — a qualifier the evidence doesn't support.
