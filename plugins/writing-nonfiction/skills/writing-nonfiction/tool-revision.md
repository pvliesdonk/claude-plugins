# Revision (generate, then revise — big to small)

Two disciplines: separate *generating* from *revising*, and revise in the right *order*.

## Generate, then revise
Don't draft and polish in the same pass — it stalls the draft, and you polish sentences you'll later cut. Get a complete, ugly draft down first ("write fast, revise slow"); fix it afterwards.

## Revise big to small (don't polish what you may cut)
Run distinct passes, largest concern first — each pass can invalidate work a smaller one did early:
1. **Developmental** — structure, argument, completeness, audience fit. Is there one governing point and does the structure deliver it? *Reverse-outline it*: list each paragraph's point; if the outline is incoherent, the structure is.
2. **Line / stylistic** — flow, emphasis, clarity per paragraph (see `tool-sentence-clarity.md`).
3. **Copyedit** — grammar, consistency, terminology, citations; an `tool-ai-tells.md` pass if AI-assisted.
4. **Proofread** — surface errors, last, on the laid-out document.

## Apply it
- Resist polishing the first draft; finish it ugly, then revise.
- Don't copyedit a section you might cut — settle structure (pass 1) first.
- Get distance: read aloud, sleep on it, or have someone else do the final surface pass (your own eye fills in what isn't there).

## Failure modes
- **Polishing a first draft** — commas before the structure is settled.
- **One undifferentiated pass** — big issues hide behind small ones.
- **Self-proofing only** — the eye you wrote with is worst at the final surface check.
