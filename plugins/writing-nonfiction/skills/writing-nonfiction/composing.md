# Composing — When No Genre Fits

Most real documents don't match a named genre exactly — a board memo, a postmortem, an internal FAQ, a release note, a strategy one-pager, a talk abstract. Don't force one of the genre files onto it. **Compose** the document instead: diagnose what it is, borrow the nearest spine, and assemble the right tools.

## Diagnose: job, reader, constraints

1. **Job** — name the **dominant purpose**: is it mainly *persuading*, *explaining*, or *reporting*? (Most non-fiction is exposition or argumentation.) A document can have sections with different jobs — but each section has *one*, and the whole needs a centre of gravity.
2. **Reader** — the specific person (often a primary decider, a secondary scrutiniser, a gatekeeper): what they know, how much time they'll give it, the decision/action it must support. (Core move 1.)
3. **Constraints** — length, format, medium, venue rules (template, rubric, page limit), and *how it'll be read* — skimmed or studied, screen or print, once or as reference.

## Compose: spine → swap → layer

- **Name the dominant purpose and hold it** — don't let an explainer drift into a pitch.
- **Borrow the nearest genre's spine, then adapt.** A board memo ≈ executive-summary lead + front-loading + argument structure; a postmortem ≈ an IMRaD-style what-happened/why/what-now arc + the gap (what we missed); an internal how-to ≈ a Diátaxis how-to; a strategy one-pager ≈ value framing + front-loading. Use the nearest genre file as a starting frame, not a cage.
- **Layer the three tiers** — pick one from each: **structure** (a template / typology) → **moves & arcs** (front-loading, the argument layout, a narrative spine) → **sentence clarity** (plain language, the prose tools). Reach into `tools.md` for each.
- **Apply the core moves regardless** — front-load the point, write to the real reader, reduce it to one spine sentence, differentiate/evidence where it persuades, revise for the way it'll be read.

## Worked examples

| Document (no exact genre) | Job | Assemble from |
|---|---|---|
| One-page decision memo | persuade/decide | exec-summary lead + SCQA/front-loading + argument structure + plain language |
| Incident postmortem | explain/report | what/why/fix arc + the gap (what we missed) + blameless plain prose + a status header if still open |
| Internal FAQ / wiki page | explain | Diátaxis how-to or explanation + plain language |
| Talk abstract | persuade/inform | abstract conventions + ABT spine + front-loading |
| Strategy one-pager | persuade | value framing + front-loading + figures |

## Failure modes

- **Template-forcing** — hammering the document into "the proposal format" when its job/reader want something else.
- **No dominant purpose** — wandering across explain/argue/report.
- **Surface-copying a genre** — its sections without its reader-logic (a "white paper" that's really a brochure).
- **Ignoring constraints** — a study-it structure for a reader who'll only skim.
